## 0. 画面の型

```tsx
const LAYOUT     = "stage";                    // 区分ごとに束ねる
const TONE       = "indigo";                   // 🔮
const DENSITY    = "normal";                   // 🔮
const UNIT       = "タスク";                    // 🔮
const CATEGORIES = ["業務", "自主活動"];         // ← 段階ではなく「区分」を束ねに使う
```

| | 選んだもの | 理由 |
|---|---|---|
| **LAYOUT** | `stage` | 3行目が「一覧でわかる」＝**業務と自主活動を並べて見たい**。`stage` は CATEGORIES ごとに束ねて各グループの合計を出す型なので、**「業務に何時間、自主活動に何時間」が1画面で並ぶ**。`queue`（待たせ順）は待っている相手がいないので合わない。`due`（期限）は期限日を持つとデータ項目が6つになるため今回は外す |
| **TONE** | 🔮 `indigo` | 1行目は「企業に勤める中堅社員」で**業種が書かれていない**。BtoB企業のオフィスワークと見て `indigo` を仮に置く。→ 確かめ方: 「お勤め先はどんな業種ですか？」 |
| **DENSITY** | 🔮 `normal` | 2行目にあるのは**時間**（業務8h・自主活動2h）で、**件数が書かれていない**。1日数件〜10件程度と見て `normal`。→ 確かめ方: 「1日に、いくつくらいのタスクを抱えていますか？」 |
| **UNIT** | 🔮 `タスク` | 本人が管理するのは案件でも現場でもなく**自分のタスク**。「9タスク」と数えるのが本人の言葉づかいに近いと思われる。→ 確かめ方: 「これ、普段なんて数えていますか？『3タスク』ですか『3件』ですか？」 |

> ⚠ `stage` は通常「未着手／進行中／完了」のような**段階**を束ねに使いますが、
> **今回は「業務／自主活動」を束ねに使います。** この2つを1画面に並べることがこの題材の本体で、
> 段階（状態）で束ねると**区分バッジが消えて本体が見えなくなる**ためです。状態は行の中に表示します。

## 1. このツールが解くこと

**今週、業務と自主活動にそれぞれ何時間を置いて、実際に何時間できたのか（そのズレ）が1画面で分かる。**

---

## 2. 使う人と、使う場面

- **使う人**: 山本さくらさん（30代・企業の中堅社員）。自分ひとりで使う。他人には見せない
- **いつ開くか**: 🔮 ① 日曜の夕方か月曜の朝に、その週の予定を置くとき ② 1つのタスクが終わった直後に、実際にかかった時間を入れるとき
  → 確かめ方: 「予定を立て直すのは、だいたいいつですか？」
- **開いて最初にしたいこと**: **業務と自主活動それぞれの「見積もり合計」と「実績合計」、その差を見る。** 次に、終わったタスクの実績時間を入れる

> この人は「外からは順調に見えている」人です。**正直な実績を入れてもらうことが成立条件**なので、
> 画面には評価・励まし・警告の言葉を出しません。**数字だけを出します。**

## 3. 画面（テンプレートの3画面をそのまま使う）

画面は **一覧 / 新規登録 / 設定** の3つのまま。ルーティングは増やしません。

### 一覧画面 ── 上から順に

1. **現在の状況**（横並びの数字3つ）
   `[ 12.0h ]見積もり合計` `[ 7.5h ]実績合計` `[ -4.5h ]差`
   ※ 実績が未入力のタスクは実績0として数えず、**実績が入っているタスクだけで差を出す**
2. **検索・絞り込み**
   キーワード検索（タイトル）／ 区分で絞る（すべて・業務・自主活動）／ 状態で絞る（すべて・未着手・進行中・完了）
3. **データ一覧**（区分ごとに束ねる）
   ```
   業務                                   見積 8.0h / 実績 6.0h    5 タスク
     月次レポートの作成         2.0h → 3.5h  [+1.5h]  完了
     後輩の設計レビュー         1.0h →   ―           進行中
   自主活動                               見積 4.0h / 実績 1.5h    3 タスク
     資格講座 第3章             2.0h → 0.5h  [-1.5h]  進行中
   ```
   1行に出るもの: **タイトル / 見積もり時間 → 実績時間 / 差 / 状態**
   ※ 区分は見出しで束ねているので、行の中に区分バッジは出しません

### 新規登録画面

タイトル・区分・見積もり時間を入れて登録する。実績時間と状態は登録後に一覧から変える。

### 設定画面

テンプレートのまま（データの全削除など）。今回このツール固有の設定は増やしません。

## 4. データ項目

**5つまで。** 6つ目を足したくなったら、代わりに1つ削ります。

| 項目 | 型 | 必須 | 例 |
|---|---|---|---|
| タイトル | 文字列 | ○ | 資格講座 第3章 |
| 区分 | 選択（業務 / 自主活動） | ○ | 自主活動 |
| 見積もり時間 | 数値（時間・0.5刻み） | ○ | 2.0 |
| 実績時間 | 数値（時間・0.5刻み） | ― | 0.5 |
| 状態 | 選択（未着手 / 進行中 / 完了） | ○ | 進行中 |

- **実績時間だけが任意**です。登録した時点ではまだ分からないため、空（`―`）で始まります
- **差（見積もり − 実績）は保存しません。** 表示するときに計算します（項目を1つ節約するため）

🔮 **「優先度」は入れません。** 6つ目になるためで、状態と並び順で代用します。
　→ 確かめ方: 「優先度は3段階でつけたいですか。それとも『今週やる／やらない』の2つで足りますか？」

🔮 **「日付」も入れません。** `stage` は期限で束ねないため、今回は使いません。
　→ 確かめ方: 「先週のぶんと今週のぶんは、分けて見たいですか？」

## 5. 操作（3つまで）

| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | **タスクを登録する**（タイトル・区分・見積もり時間） | 一覧の「業務」か「自主活動」のグループに1行増える。そのグループの**見積もり合計と、上部の見積もり合計が増える** |
| 2 | **実績時間を入れる**（一覧の行から直接） | その行に **`2.0h → 0.5h [-1.5h]`** の形で差が出る。グループの実績合計と、上部の実績合計・差が更新される |
| 3 | **状態を変える**（未着手 → 進行中 → 完了） | 行の状態表示が変わる。状態の絞り込みで出し分けられるようになる |

> **絞り込みと検索は、テンプレートに既にあるものをそのまま使います**（3画面の一覧に含まれる）。
> 操作を1つ増やす代わりに、**実績時間の入力を一覧から直接できること**に枠を使います。
> 2時間予定が30分になったという事実は、**この操作でしか記録に残らない**ためです。

## 6. やらないこと

`CLAUDE.md` 3章の3つ:

1. **カレンダー連携（Google / Outlook の同期）をしない。** 連携した瞬間に「予定」が主役になり、このツールの本体である「実績とのズレ」が薄まるため
2. **AIによる自動優先度づけ・自動スケジューリングをしない。** 本人の係数が貯まる前に機械が並べ替えると、外れた理由が本人に残らないため
3. **他人との共有・チーム機能（割り当て・コメント・上司への共有）をしない。** 「外からは順調に見えている」人は、見られる前提だと正直な実績を入れなくなるため

今回の範囲外（第2〜3回で扱う）:

4. **ログイン・課金・メール送信・通知・リマインダーを作らない**
5. **グラフ・週次の推移表を作らない。** 3行目に「視覚的に」とあるが、**まず1週間ぶんの数字が並ぶことを成立させる。** 推移は、データが数週間貯まってからでないと意味のある形にならない
6. **新しいライブラリを追加しない。** テンプレートの構成（Next.js + プレーンCSS）のまま作る

**画面に出さないもの**（`CLAUDE.md` 5-2章）:

7. **LP（キャッチコピー・課題説明・CTA・営業文）を作らない**
8. **`docs/` の中身（🔮の仮説・出口の3点・競合分析・やらないこと）を画面に出さない**
9. **「疲労」「メンタル」「燃え尽き」等の言葉を画面に出さない。** 効能表現になり、医療・健康領域とみなされるリスクがあるため（`CLAUDE.md` 4章③）。**画面が扱うのは「時間」と「量」だけ**

## 8. 保存方法

`localStorage` に**1つのキー**で保存する。

```
キー名: task-hours-data
```

- `useEffect` の中でだけ読み書きする（サーバー側に `localStorage` が無いため、外で読むとビルドが落ちる）
- 読み込みが終わる前に保存を走らせない（`loaded` フラグを使う。`CLAUDE.md` 5-2章の書き方に従う）

> ※ 端末ごとの保存です。複数人での共有は第3回で扱います。

## 9. ダミーデータ

初回表示で寂しくないよう、サンプルを3件入れる。**実在の人名・連絡先は使わない。**

| タイトル | 区分 | 見積もり | 実績 | 状態 |
|---|---|---|---|---|
| 月次レポートの作成 | 業務 | 2.0 | 3.5 | 完了 |
| 後輩の設計レビュー | 業務 | 1.0 | （空） | 進行中 |
| 資格講座 第3章 | 自主活動 | 2.0 | 0.5 | 進行中 |

- 1件目は**業務が見積もりを超えた**例（+1.5h）
- 3件目は顧客の3行目そのままの例。**2時間の予定が30分**（-1.5h）
- 2件目は**実績が未入力**の状態。`―` の表示を確認するために入れる
